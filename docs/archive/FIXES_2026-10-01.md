# Authentication & Security Fixes - 2026-10-01

## Summary

Implemented critical security fixes and operator authentication system to enable production deployment.

## Changes Made

### 1. Backend Security Hardening

**core/config.py:**
- Auth misconfiguration now raises ValueError (fail-fast)
- Server refuses to start if REQUIRE_AUTH=true but OPERATOR_TOKEN not set
- Removed emoji from logs for production compatibility

**core/biblelive_server.py:**
- Added secrets.compare_digest() for constant-time token comparison
- Protected /api/state endpoint with authentication
- Removed emoji from logs

### 2. Frontend Operator Authentication

**frontend/src/operator/App.tsx:**
- Token input UI with localStorage persistence
- Logout functionality
- WebSocket includes token: /ws/operator?token=...
- Detects auth failure (code 1008) and re-prompts

**frontend/src/shared/useWebSocket.ts:**
- Added onClose callback option
- Prevents reconnection on auth failures (code 1008)

### 3. New Documentation

**SECURITY.md:** Complete security guide with:
- Authentication architecture
- Production deployment examples
- Systemd configuration
- Nginx with log redaction
- Security checklist

## Migration Guide

1. Generate token: python3 -c "import secrets; print(secrets.token_urlsafe(32))"
2. Set BIBLELIVE_REQUIRE_AUTH=true and BIBLELIVE_OPERATOR_TOKEN=... in .env
3. Restart server
4. Access /operator and enter token when prompted
