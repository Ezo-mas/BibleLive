# Exact versions for every Python package BibleLive installs, direct or indirect.
#
#   pip install -e "./backend[dev,audio]" -c backend/constraints.txt
#
# backend/pyproject.toml says what BibleLive needs (ranges); this file says which
# versions were actually tested together. Without it a fresh install takes the
# newest release of everything on the day, so two machines set up a week apart
# can behave differently and a broken upstream release reaches production the
# next time someone reinstalls. A constraint only applies when the package is
# installed, so one file serves every platform and extra; the few lines that
# differ by platform or Python version carry markers.
#
# Verified (2026-10-13):
#   - the full backend suite and mypy pass against these versions on Windows,
#     Python 3.12 (with the audio extras and the CUDA wheels);
#   - every pin resolves with Linux x86_64 wheels on Python 3.11, 3.12 and 3.13
#     (the CI matrix), apart from webrtcvad, which only ships as source there.
#   The Linux-only lines (uvloop, webrtcvad) and the Python 3.11 lines (numpy,
#   av) were not exercised by that local run; CI exercises them.
#
# Updating (deliberately, not as a side effect of an install):
#   1. In a fresh venv: pip install -e "./backend[dev,audio,cuda]" --upgrade
#      (no -c), or upgrade only the package you mean to move.
#   2. Run the Definition of Done checks (AGENTS.md). If faster-whisper,
#      ctranslate2, onnxruntime, tokenizers, av, numpy, or webrtcvad changed,
#      that can change what is detected: run the benchmark before and after.
#   3. pip list --format=freeze --exclude-editable, and copy the new versions in
#      here, keeping the marker lines. Leave out pip itself.
#   4. Let CI confirm Python 3.11-3.13 on Linux.
